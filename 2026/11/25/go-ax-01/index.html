AX 学习 01：快速入门

发表于 2026-11-25 分类于 Go

在本地运行 Claude Code、Codex 这样的编程智能体，通常从准备代码仓库和模型访问凭据开始。可当任务多起来，问题就变了：不同任务的依赖会不会冲突，执行中的程序能访问哪些服务，工作到一半能不能暂停，之后又该从哪里继续。AX 把这些执行环境问题放到了任务之外。你用清单描述任务、工作区和网络权限，它负责把程序放进独立沙箱，准备文件，再启动任务。任务程序可以是 Claude Code、Codex 等智能体 CLI，也可以是自定义脚本。

本文从一个只执行 shell 命令的 Task 开始，先熟悉提交、启动和查看结果，再增加 Workspace 与 Gateway，完成一次真实的模型 API 调用。所有清单都会完整列出，读者可以直接保存并执行。

项目定位

AX 是面向智能体任务的声明式编排工具，建立在 Agent Substrate 之上。声明式指的是把任务所需的镜像、命令和环境写进清单，再由 AX 创建执行环境。

AX 负责管理任务，任务中的程序负责完成具体工作。因此，同一套机制既能运行一条 shell 命令，也能运行 Claude Code、Codex 等智能体 CLI。本文使用任务镜像自带的 curl 调用模型 API，先把执行链路说明白。

AX 的命令和清单接近 Kubernetes，但 Task 等资源由 AX 保存到 PostgreSQL，并不是 Kubernetes CRD。提交任务使用 ax apply，管理 Kubernetes Secret 才使用 kubectl。

对象与组件

四种资源

资源 职责 本文用法
Task 描述启动命令、计算配置和资源引用 先执行 shell 命令，再执行模型请求
Workspace 准备文件、仓库和依赖，可提供默认计算配置 在任务工作目录中放入请求文件
Gateway 限制外部访问，并为请求注入凭据 允许访问模型接口并替换认证头
Model 保存模型提供商、模型名称和 Secret 引用等配置 本例不需要创建

Model 资源不会自动替任意程序配置模型。当前 TaskSpec 没有绑定 Model 的字段，本文通过请求文件指定模型，通过 Gateway 提供访问凭据。

Task 与引用的 Workspace、Gateway 需要位于同一个 atespace，本文统一使用 default。它与 AX 服务所在的 Kubernetes 命名空间 ax-system 是不同的范围。

执行组件

ax 是命令行入口，ax-server 接收请求并协调任务，PostgreSQL 保存 AX 资源。Agent Substrate 提供沙箱、worker 调度和快照；沙箱内的 ax-runner 准备工作区并启动任务命令。

ax-server 管理执行环境，具体命令在任务沙箱中运行。

环境准备

本文从源码构建，使用同一版本的 CLI、服务端和 runner。需要准备：

  • 容器环境：运行中的 rootful Docker；容器主机的 Linux 内核至少为 6.8，内存至少 4 GiB，建议 6 GiB 以上。
  • 构建工具：Go 工具链，设置 GOTOOLCHAIN=auto 后按项目要求选择版本。
  • 网络与磁盘：构建环境和集群能够访问软件源、镜像仓库、运行时下载地址及模型接口，并为缓存、数据库和快照预留空间。

macOS 需要检查 Docker Desktop、OrbStack 或 Colima 内部 Linux 虚拟机的配置。内核低于 6.8 时，本地集群启动检查会失败。

本次实测环境需要出网代理，Docker 构建、Kind 节点、下载运行时的 atelet，以及出站网关分别做了代理适配。以下操作以这些网络访问条件已经满足为前提；仅设置当前终端的 HTTP_PROXY 并不能让所有组件自动使用代理。

小结

AX 将任务的执行条件写成清单：Task 指定运行什么命令，Workspace 准备文件和依赖，Gateway 管理外部访问与凭据注入。ax-server 负责协调这些配置，Agent Substrate 提供沙箱，ax-runner 在沙箱内准备工作区并启动程序。

从 shell 命令到模型请求，基本流程都是先用 ax apply 创建资源，再用 ax resume 启动任务，通过状态和输出检查结果。掌握这条流程后，就可以把示例中的 curl 换成智能体 CLI，逐步加入代码仓库、依赖和更具体的任务目标。
